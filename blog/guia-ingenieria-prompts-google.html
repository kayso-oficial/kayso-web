Ingeniería de Prompts: Guía Práctica de Google

No hace falta ser científico de datos para escribir un buen prompt, pero sí necesitás técnica. Analizamos el whitepaper oficial de Google sobre cómo configurar salidas, estructurar contextos y usar razonamiento avanzado en LLMs.

La ingeniería de prompts es mucho más que escribir una frase en un chat; es un proceso iterativo de diseño, prueba y ajuste. [cite_start]Los Modelos de Lenguaje Grande (LLMs) son motores de predicción: toman un texto de entrada y calculan cuál es el token (pieza de palabra) más probable para continuar la secuencia[cite: 30, 32].

En esta guía, basada en la documentación técnica de Google, desglosamos cómo controlar estas predicciones para pasar de respuestas genéricas a soluciones de ingeniería precisas.

Configuración de Salida: El Control del Motor

Antes de escribir una sola palabra, debés entender los parámetros que controlan la "creatividad" del modelo. Si usás la API de Gemini o Vertex AI, esto es crucial:

  • Temperatura: Controla la aleatoriedad. [cite_start]Una temperatura baja (cercana a 0) hace que el modelo sea determinista (ideal para código o matemáticas)[cite: 82, 84]. [cite_start]Una temperatura alta fomenta la diversidad y creatividad, pero aumenta el riesgo de alucinaciones[cite: 83].
  • Top-K y Top-P: Son filtros de selección. [cite_start]Top-K elige entre las K fichas más probables (ej. las 3 mejores)[cite: 98]. [cite_start]Top-P selecciona el conjunto mínimo de fichas cuya probabilidad acumulada no supera un valor P (ej. 0.95)[cite: 105]. Jugar con estos valores ajusta cuán "obvia" o "inesperada" será la siguiente palabra.

Técnicas de Prompting Esenciales

1. Zero-shot vs. Few-shot

[cite_start]El enfoque más básico es el Zero-shot: simplemente pedir lo que querés sin ejemplos[cite: 148]. Sin embargo, para tareas complejas, el estándar de oro es el Few-shot prompting: proporcionar al modelo 3 a 5 ejemplos de entrada/salida deseada antes de tu petición real. [cite_start]Esto enseña al modelo el patrón, formato y estilo que debe imitar[cite: 175, 182].

2. Sistema, Contexto y Rol

[cite_start]Una estructura robusta divide el prompt en tres capas[cite: 216]:

    [cite_start]
  • Prompt del Sistema: Define el "panorama general" y las reglas inquebrantables (ej. "Sos un experto en Python, devolvé solo código JSON")[cite: 217, 243].
    • [cite_start]
  • Contexto: Información de fondo relevante para la tarea actual[cite: 219].
    • [cite_start]
  • Rol: Asignar una identidad (ej. "Actuá como un guía turístico sarcástico") ayuda al modelo a ajustar el tono y vocabulario[cite: 221, 295].

Razonamiento Avanzado

Cuando los modelos fallan en lógica o matemáticas, no es por falta de conocimiento, sino de proceso.

Chain-of-Thought (CoT)

[cite_start]Esta técnica fuerza al modelo a generar "pasos intermedios de razonamiento" antes de dar la respuesta final[cite: 445]. Es tan simple como agregar "Pensemos paso a paso" al final del prompt, o dar ejemplos donde se desglose la lógica. [cite_start]Esto mejora drásticamente la precisión en problemas aritméticos o lógicos[cite: 446, 453].

ReAct (Reason & Act)

[cite_start]ReAct es el paradigma que permite a los LLMs actuar como agentes[cite: 585]. Combina el razonamiento verbal con el uso de herramientas externas (como búsqueda en Google o ejecutar código Python). [cite_start]El modelo "piensa" qué necesita, "actúa" (ejecuta una búsqueda), "observa" el resultado y vuelve a pensar[cite: 588, 590].

Automatización y Salidas Estructuradas

Para integrar LLMs en software real, el texto libre es un problema. [cite_start]La mejor práctica es forzar salidas en JSON definiendo un esquema claro en el prompt[cite: 973, 976]. Esto facilita el parseo y reduce alucinaciones. [cite_start]Además, existe la Ingeniería de Prompts Automática (APE), donde usamos un LLM para escribir y optimizar los prompts de otro LLM[cite: 645, 646].

Action Points: Tu Checklist de Calidad

Antes de desplegar un prompt en producción, verificá estos puntos:

Usá Instrucciones Positivas

Decile al modelo "lo que debe hacer" en lugar de una lista larga de restricciones sobre "lo que no debe hacer". [cite_start]Evita confusiones[cite: 912, 916].

Estructurá con Ejemplos

Incluí siempre 3-5 ejemplos (Few-shot) de alta calidad. [cite_start]Es la herramienta de enseñanza más potente para el modelo[cite: 870, 966].

Especificá el Formato

[cite_start]

Si necesitás datos, pedí JSON o XML explícitamente y proporcioná un esquema o plantilla vacía[cite: 973, 997].

Documentá e Iterá

[cite_start]

Mantené un registro (como una hoja de cálculo) con versiones del prompt, temperatura usada y calidad de la salida[cite: 1045, 1052].

Conclusión

La ingeniería de prompts se está moviendo de un arte oscuro a una disciplina de ingeniería sistemática. [cite_start]Ya sea usando Tree of Thoughts para explorar múltiples vías de solución [cite: 569] [cite_start]o Step-back prompting para abstraer problemas[cite: 382], la clave está en guiar al modelo con claridad, contexto y restricciones estructuradas.

Key Takeaways

Resumen Técnico

Conceptos clave para dominar la API de Gemini y otros LLMs:

  • Temperatura: Usá 0 para lógica/código; 0.7+ para creatividad.
  • Few-Shot: Dar ejemplos mejora drásticamente la adherencia al formato.
  • CoT: "Pensemos paso a paso" reduce errores lógicos.
  • JSON: Usá esquemas para integrar salidas en aplicaciones.
